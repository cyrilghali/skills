# Default style: plain walkthrough

This file is taste, not research. It sets the shape and tone of a video when the user has no style of their own. No published study backs these choices; where a rule here bends a sourced rule in `REFERENCE.md`, the sourced rule wins.

To use your own style, replace this file with yours and keep its name. Keep the section headings so the steps still find the length default and the beat order.

## Length

- With no length in the request or the brief: about 90 seconds, inside 60 to 120.
- A topic longer than about two minutes becomes chapters of about two minutes each, in the same `beats.json`. Prefix each beat id with its chapter (`c2-ask`).

## Beat order

| Beat | What it does |
|---|---|
| Hook | The question the viewer wants answered. |
| Concrete case | The case from `script.md`, with its real numbers and names. |
| Build | One step per beat, each changing the picture already on screen. |
| General rule | The pattern, said only after the viewer has seen it work once. |
| Payoff | The answer to the hook, in one sentence, on the final picture. |

A short video keeps the hook, the case and the payoff, and folds the rule into the payoff.

In a longer video, each chapter has its own hook, build and payoff. Open each chapter with one sentence that ties what the viewer just learned to what the chapter asks. In a series, the last beat may preview the next episode's question.

## Story

- Take the case from things the viewer already knows, with real numbers and names.
- When the case has an actor, say what the actor wants in the first beat.
- Place the wrong idea late, as the twist: show it fail on screen before explaining why.
- Each chapter happens in one scene, so the picture changes rather than cuts.

## Voice

- Sentences of about 15 words, one idea each.
- One word for one thing across the whole video. In a series, keep a glossary and check each episode against it.
